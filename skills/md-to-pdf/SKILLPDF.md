# Markdown → 商务风格 PDF

把一份 Markdown 报告转成可以直接发给 HR、猎头、面试官看的 PDF。

## 一、执行流程

### 第 1 步：确认输入文件

如果内容还在对话里没落盘，**先写成 `.md` 文件**再转换。不要试图把长文本直接塞进命令行。

```bash
# 内容已在项目文档里 → 先取出来存成本地 md 文件
```

### 第 2 步：确认环境（只在首次运行报错时才需要）

```bash
python3 -c "import markdown" && (python3 -c "import weasyprint" 2>/dev/null || python3 -c "from playwright.sync_api import sync_playwright" 2>/dev/null) && echo OK
fc-list :lang=zh | head -1   # 必须有输出，否则中文会变成方框
```

- 缺 `markdown`：`pip install markdown --break-system-packages`
- 两个渲染引擎都没有：装其一即可
  - `pip install weasyprint --break-system-packages`
  - 或 `pip install playwright --break-system-packages && playwright install chromium`
- 缺中文字体（Linux）：`apt-get install -y fonts-noto-cjk`
- **在 Anthropic 云端环境里，Chromium 通常已预装，直接跑脚本即可，不必先装 weasyprint。**

### 第 3 步：转换

```bash
python3 <skill_dir>/scripts/md_to_pdf.py 输入.md -o 输出.pdf \
  --author "姓名" --kicker "JD 分析报告"
```

### 第 4 步：目检（不可跳过）

生成后必须抽查，中文排版最容易在分页和表格上翻车：

```bash
pdftoppm -png -r 70 输出.pdf /tmp/chk    # 转成图片
```

然后用 Read 工具看 **封面页 + 至少一页正文**，确认：
中文没有变方框 · 表格没有溢出页面右边 · 标题没有孤零零留在页底 · 评分条和结论框有正确渲染 · 页码连续。
发现问题按「五、排版微调」处理，改完重新生成。

### 第 5 步：交付

用 SendUserFile 发给用户；若用户连接了本地文件夹，再用 device_commit_files 写回去。

## 二、命令行参数

| 参数 | 说明 |
|---|---|
| `input.md` | 输入文件（必填） |
| `-o out.pdf` | 输出路径，默认同名 .pdf |
| `--title` | 封面主标题。不填则自动取文档第一个 `# 一级标题` |
| `--subtitle` | 封面副标题，一句话说明这份报告是给谁、看什么 |
| `--author` | 封面「编制」署名 |
| `--kicker` | 封面顶部小标签，如「JD 分析报告」。不填会按内容自动判断 |
| `--header` | 页眉文字，默认取标题（超过 46 字会截断） |
| `--date` | 日期，默认今天 |
| `--toc` | 加一页目录（正文超过 6 页时建议加） |
| `--no-cover` | 不要封面页（短文档、单页速览时用） |
| `--no-h1-break` | 不在每个一级标题前强制分页（**短报告务必加，否则会有大量空白页**） |
| `--css` | 换一套自定义样式表 |
| `--engine` | `auto`（默认）/ `weasyprint` / `chromium` |
| `--keep-html` | 保留中间 HTML，方便排查样式问题 |

**分页规则要点：** 脚本默认让每个 `#`（一级标题）另起一页。
- 报告用 `#` 分大章节 → 保持默认
- 报告只用 `##`/`###` 分模块（求职 Skill 04/05/06 的产出多属这种）→ 无影响，正文会连续流动
- 报告用了很多 `#` 但每节只有几行 → 加 `--no-h1-break`

## 三、针对 04 / 05 / 06 的预设

| 来源 | 推荐参数 | 排版重点 |
|---|---|---|
| **04 JD 分析** | `--kicker "JD 分析报告" --subtitle "<公司> · <岗位> 匹配度与投递建议"` | 匹配度评分条、差距点表格、投递建议结论框 |
| **05 行业与市场分析** | `--kicker "行业与市场分析报告" --subtitle "<行业/赛道> 产业链、市场规模与竞争格局"` | 市场规模表、机会地图、趋势要点框、数据来源与不确定性提示 |
| **06 公司背景研究** | `--kicker "公司调研报告" --subtitle "<公司> 业务、组织与面试情报"` | 竞争格局对比表、组织架构层级、`--toc`（通常较长） |

文件命名建议：`公司_岗位_JD分析_20260821.pdf`，方便日后按公司检索。

**报告如果引用了市场数据或薪酬区间**，正文里保留来源标注和不确定性说明——PDF 会被转发出去，脱离对话上下文后这些标注就是唯一的可信度线索。

## 四、写 Markdown 时的三个约定

脚本会自动识别以下写法，把它们渲染成视觉元素。生成 04/05/06 报告时按这个格式写，PDF 会好看很多。

### 1) 评分 → 可视化进度条

独立成行、`标签：分子/分母` 的格式会被渲染成带进度条的评分卡（≥75% 绿色，50–75% 橙色，<50% 红色）：

```markdown
综合匹配度：8/10

面试成功概率：6.5/10 （硬性门槛全部满足，行业经验存在缺口）
```

括号里的补充说明会变成评分条下方的小字注释。
关键词包括：匹配度、契合度、评分、得分、成功概率、推荐指数、score、fit。
**表格单元格里的 `8/10` 不会被改动**，仍是普通文本。

### 2) 结论 / 风险 → 高亮框

三种写法都能生成高亮框：

```markdown
:::结论
核心能力高度匹配，差距均可弥补，建议优先投递。
:::

:::风险
硬性门槛中的「5 年经验」按当前简历口径只有 4.5 年，投递前需要调整口径。
:::
```

可用的框类型：`结论`/`建议`（绿）、`注意`（橙）、`风险`（红）、`要点`（蓝）、`提示`（灰蓝）。

此外，以 `**建议：…**`、`**结论：…**`、`**投递建议：…**` 开头的段落，以及含「建议 / 结论 / 风险」关键词的引用块（`>` 开头），会被**自动**升级成高亮框，颜色按语气判断（出现「不建议 / 谨慎 / 风险」→ 红，「注意 / 待验证」→ 橙，其余 → 绿）。

### 3) 表格宁窄勿宽

A4 纵向正文宽度约 174mm。**列数不要超过 5 列**，表头保持短词。
超过 5 列的对比（比如同时比 6 个 JD）拆成两张表，或改成「每个对象一小节」的结构。

## 五、排版微调

目检发现问题时按下表处理，改完重新生成并再看一次：

| 症状 | 处理 |
|---|---|
| 中文变方框 | 装 `fonts-noto-cjk`，或用 `--css` 指定一份改了 `font-family` 的样式 |
| 大量空白页 | 加 `--no-h1-break` |
| 表格右侧被切 | 减少列数 / 缩短表头 / 把长单元格改成列表 |
| 标题掉在页底、内容在下一页 | 已用 `page-break-after: avoid` 处理；仍出现就在该标题前后调整内容长度 |
| 封面标题太长换三行 | 用 `--title` 传一个短标题，长版本放 `--subtitle` |
| 想换主色 | 复制 `assets/business.css`，改开头 `:root` 里的 `--primary` 等变量，用 `--css` 传入 |
